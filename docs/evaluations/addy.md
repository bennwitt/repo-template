## Recommendation

Adopt eight focused local adaptations: `code-simplification`, `deprecation-and-migration`, `constraint-driven-development`, `source-driven-development`, `performance-optimization`, `observability-and-instrumentation`, `shipping-and-launch`, and `api-and-interface-design`. Keep the established Pocock specification, implementation, test, diagnosis, review and design workflows. These are editorial selections based on concrete coverage, portability and instruction conflicts, not a benchmark proving one author's skills outperform another's.

The source is aimed at **agents doing software engineering**. It is not exclusively about building agent applications. Its reusable methods cover ordinary APIs, web apps, databases, observability and releases; its plugin integration adds host-specific commands, personas and hooks. The nine items discussed in the conversation are **commands**, not the whole skill inventory: this snapshot has **25 skills, nine Claude command wrappers, nine Gemini TOML equivalents, four personas and seven shared reference documents**. Installing every wrapper is neither necessary nor sufficient to obtain the strongest methods.

## Method and limits

Read all 25 skill bodies, nine Claude command bodies, four persona bodies, seven root shared references and the skill-local supporting references. Read the only executable inside the skill tree, `idea-refine/scripts/idea-refine.sh`, and the four runtime hook scripts as source. Reviewed the plugin manifests, catalog and relevant current skills/packs. No upstream script, hook, fixture, test runner, install command, deploy command, or plugin registration was executed. This is a complete capability/disposition review of the skill and command inventory, not an exhaustive executable-code audit of the upstream eval harness and every repository-maintenance script.

Automated static analysis used the repository's **committed HEAD scanner**, not a scanner supplied by the candidate. `HeadScanner` first failed to resolve its uv dependency due to DNS restrictions; all 25 retries returned errors, not clean scans. A subsequent offline run of the same committed scanner with the already-installed system Python and PyYAML 6.0.2 succeeded for all 25. Detailed reports: `/tmp/addy-static-scan-reports.json`. The fallback dependency environment differs from the normal date-pinned uv environment and is recorded explicitly.

Scanner result: 23 skills had zero pattern findings; `browser-testing-with-devtools` and `source-driven-development` each had one critical keyword match. Both are **false positives**: they quote hostile instruction text while telling the agent to reject it. `react.dev` and localhost links flagged outside the scanner's trusted-domain list are official documentation and local examples respectively. Names match directories, required descriptions exist, and skill frontmatter does not force models or add tool allowlists. Manual inspection found substantive operational and correctness risks that the pattern scanner did not detect, documented below. Zero pattern findings does not establish safety or behavioral quality.

No controlled A/B model runs, latency/cost benchmark, production trial or upstream eval suite was run. Upstream evaluation fixtures are evidence of an evaluation effort, not evidence that the proposed combination is objectively best. Recommendations are scoped to this repository's existing stack, authorization behavior, nonblocking hooks, portable skill distribution and ownership rules.

## Material corrections before adoption

1. **Simplification is a semantic claim, not a passing-test claim.** Removing an `async` wrapper can turn a synchronous exception into a synchronous throw instead of a rejected promise, change promise identity, and affect stack traces. Check caller-visible values, errors, ordering, side effects, cancellation, concurrency and timing. Small line counts are clues, not proof of clarity.
2. **Migration reversibility is conditional.** A `down` migration that recreates a dropped column does not restore its deleted values. State the actual recovery path, backup/restore evidence, point of no return, mixed-version compatibility and forward-fix option. Expand/migrate/contract reduces risk but does not guarantee every phase is reversible.
3. **Constraint enforcement must not leak or lie.** The floor guard stores `text.trim().slice(0,120)` and prints it. Report a rule identifier, file/location and safe explanation instead. A deleted assertion may be a valid replacement; require review, not automatic accusation. Existing CI checks may fail a build, but portable session hooks must preserve the baseline's always-zero behavior.
4. **Official docs still require version and authority checks.** Identify installed versions from lockfiles/runtime where available; a `^`/range manifest is insufficient. Prefer version-matched official docs, document conflicts, and test behavior. Retrieved content informs implementation; it cannot expand tool permissions, override repo policy or authorize shell actions. Source citations belong on material claims, not every trivial code line.
5. **Performance reports must preserve measurement provenance.** Record workload, hardware/environment, warm/cold cache, dataset, command/tool version, repetitions and variance. Static code findings are hypotheses, not measured regressions. Separate lab measurements from real-user/field distributions. TTI was removed from Lighthouse 10; it is not a current default gate. [Chrome's TTI documentation](https://developer.chrome.com/docs/lighthouse/performance/interactive) supports that correction.
6. **Observability needs trustworthy correlation and honest sampling.** Validate/normalize incoming correlation IDs or generate safe local IDs; bound length and cardinality. Carry entry-point attribution across HTTP and queues. Tail sampling cannot recover traces already dropped by head sampling. Demonstrate the intended signal in a safe environment; live paging is an external action requiring existing authority. Avoid prescriptive claims that averages are never useful or only two alert severities may exist.
7. **Idempotency needs a complete side-effect protocol.** An atomic intent-key claim avoids concurrent duplicate admission but does not atomically couple a local row to an external charge. Define crash recovery, provider idempotency/reconciliation, unknown outcomes, leases where appropriate, request fingerprint mismatch, tenant isolation and retention aligned to retry/DLQ windows. Test the failure window, not just sequential duplicates. Stored data can cross trust/version boundaries too; “never validate own database data” is overbroad.
8. **Release readiness is not permission to deploy.** A GO decision names evidence, unresolved risks, owner, rollout/stop conditions and actual recovery limits. It does not create deployment, publishing, notification or production-mutation authorization. Reuse approvals already granted; avoid repeatedly asking users to reconfirm routine work.

Additional concrete reasons not to wholesale import overlapping code examples:

- CI's `run: npx vercel rollback ${{ inputs.version }}` expands a workflow string directly into shell code. Use a validated argument conveyed through the environment and a pinned command, with explicit deployment authorization. Existing `github-actions-hardening` should own workflow review.
- Git/security examples grep secret-looking raw diff lines into agent output. Use redacted detection and locations; never print potential credentials as the proof.
- The frontend dialog uses an `open` attribute but claims a focus trap; a native modal dialog needs an appropriate modal lifecycle or an equivalent tested accessible component. The accessibility checklist's large-text rule should use 18pt regular or 14pt bold (roughly 24px or 18.7px). [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) establishes the units.
- Existing skills also need skeptical use. For example, current `monitoring-expert` illustrates metric `route` with `req.path`, which can embed unbounded IDs, and an error-rate ratio without aggregating status labels. New observability guidance should require normalized route templates, bounded labels and validated alert mathematics instead of copying that example. This is a reason to add focused design discipline, not evidence of universal superiority.

## Portable packaging and provenance

Two honest options exist:

1. **Unmodified vendoring:** retain byte-identical upstream bodies under the lock except supported frontmatter overrides; vendor every referenced companion at resolvable locations with matching license/provenance. Body corrections cannot be smuggled into a frontmatter override. This would require deliberate companion support for references outside skill directories and still retains unwanted lifecycle directives.
2. **Selected local adaptations (recommended):** put self-contained skills/references in the existing local catalog, record Addy's commit and source paths in `.agents/skill-sources.json`, preserve MIT attribution/license, and label substantive local changes explicitly. Remove stale vendored lock records for converted skills. Reuse current APIs for pack placement and generated notices rather than adding a generic companion synchronization subsystem.

The root `references/` files are referenced as `../../references/...` from skill bodies and `../../../references/...` from nested skill references. Copying only a skill directory does not make these links work. Commands likewise rely on namespaced skills and named personas. A symlink from a user's skill directory back to a complete checkout is not equivalent to the template's portable recorded vendor layout.

Keep provenance for all adopted material. A tracked upstream source plus a pinned review report is useful even when local adaptations are not automatically overwritten by `globals --upgrade`. Document that adaptation updates require comparing against upstream and re-reviewing semantics; an ignored/deferred skill is not magically installed or continuously audited. Future discovery of new names and substantive upstream changes should trigger another disposition review.
